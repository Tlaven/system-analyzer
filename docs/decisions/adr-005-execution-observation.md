# ADR-005: 执行观测立柱——推翻"step 推进不激活"(方向已定,实现待做)

## 状态

accepted(方向与分界已定;MVP 实现为未完成事项,见 docs/roadmap.md)

## 背景

L1 立项时写死"不做时序动画(执行引擎的 step 推进保持不激活,但单次重算通过 propagate/evalTransforms 走响应式路径)"。

复盘后判定:这个"不做"其实 стоимости三个不同的东西,应拆分。项目名"系统分析器"承诺的不是"能让系统转起来"(模拟),而是"转起来之后能看出东西"(分析)。画布通道盘点(2026-09-14)确认:结构层齐备、执行层几乎零显示——用户无法不打开代码面板回答"这里有没有环/这个值过去怎样/改了会怎样"。

## 考虑过的方案

### 方案 A: 维持纯静态可视化,换掉"分析器"命名(被拒)

- 优点:零改动
- 缺点:名不副实;执行引擎骨架(topo/stepAndHistory/transform)早已存在却闲置,是最大的半成品
- **拒绝理由**:引擎与 transform 的设计已经为"动"付了架构成本,不用它=浪费了已付的税

### 方案 B: 直接做实时流动可视化(Proxy 化 attrs,赋值即图变)(远期,非本期)

- 优点:无缝 live 体验
- 缺点:Proxy 破坏 attrs 对象恒等(edge.target 靠 === 识别),需 memoization 表,伤及 JSON roundtrip 与双身份系统地基
- **拒绝理由**:抽水太多;L1 版步进同步已覆盖核心语义,等语义确认后再评估

### 方案 C: 交互式步进观测(采纳,分三分件)

- 属性时序记录 + 步进播放控制 + 环路视觉标记
- 数据流:观测数据是**演化层**——易失、不入 sourceCode、不入 URL(reset 即清)
- 演示式自动动画(edgeAnim 样式项)维持样式层,不是产品支柱

## 选择

选方案 C。"不做时序动画"原条款修订为:不做的是**全自动演示动画**;**交互式步进观测**从"不激活"转为**第二支柱方向**。区分判据:前者无人在场也无新信息,后者每次步进都产出用户主动消费的观测结果。

## 后果

### 正面后果

- 产品身份成立:结构可视化 + 语义可执行 + 时序观测,三柱齐名"系统分析器"
- 探测边(双层边,另一方向计划)与观测属同一哲学——画面服务于"理解运行中的系统"

### 负面后果

- L1 的防溢出哲学受考验:观测 UI 必须自律(主要活在 panel/tooltip,画布不加新卡片,minimal 档零新增)
- 引擎路径被激活后,性能预算(load 超时/无限循环)从"理论问题"变"实际风险"(Web Worker 化暂缓,先靠防呆 + 已有的 100ms 超时)
